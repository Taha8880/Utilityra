# المهندس التقني (Technical Engineer) — ما هو منفّذ فعلًا

| المستوى | الوصف | الحالة |
|---|---|---|
| 1 — اكتشاف | `monitor.yml` كل 30 دقيقة (`scripts/monitor.mjs`) و`/api/admin/engineer/run` يفحصان الصفحات/sitemap/robots/404/الروابط القديمة/health | منفّذ + مُختبر (tests/worker.test.mjs، فحص اصطناعي) |
| 2 — تسجيل وتشخيص | كل فشل = Issue في GitHub (label `incident`) وصف في جدول `incidents` بـ D1 مع تشخيص بالذكاء الاصطناعي (سبب محتمل، الملفات، إصلاح مقترح، الاختبار المطلوب) | منفّذ؛ التشخيص يحتاج مزود AI مفعّلًا |
| 3 — إصلاح | **غير مؤتمت عمدًا.** الإصلاح المقترح يُراجَع بشريًا ويمر عبر CI (`ci.yml`) قبل النشر. لا يوجد نشر تلقائي لتعديل غير مختبر | سياسة، وليست ميزة ناقصة |

إغلاق الحادث تلقائيًا عند نجاح الفحوص التالية (الـ Issue وسجل D1).

## الإصلاح بالذكاء الاصطناعي (PR فقط)
`scripts/engineer-fix.mjs` + `.github/workflows/ai-engineer.yml`: يقرأ تقرير العطل، يرسل الملفات ذات الصلة إلى نموذج (Anthropic أو OpenAI)، يطبّق تعديلات مطابقة تمامًا على فرع، يشغّل `npm test`، وإذا نجحت يفتح **Pull Request** للمراجعة. لا يدمج ولا ينشر، ولا يلمس workflows أو wrangler.toml أو الأسرار.
التفعيل: أضف سر GitHub باسم `ANTHROPIC_API_KEY` (أو `OPENAI_API_KEY`). تشغيل يدوي: Actions → AI engineer → Run workflow واكتب المشكلة.
**لم يُجرَّب مع نموذج حقيقي** (لا مفتاح في بيئتي)؛ منطق الحماية (قائمة الملفات المسموحة، مطابقة واحدة، فشل الاختبارات) هو ما كُتب لأجله.
